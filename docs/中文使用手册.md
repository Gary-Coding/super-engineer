# super-engineer 中文使用手册

这份手册用一个真实的供应链中台需求，演示如何使用 `super-engineer-workflow`。

示例需求：

> 经销商用户列表接口增加手机号精确筛选，要求兼容旧查询行为，并补齐 controller / service 层测试。

手册覆盖以下内容：

- 工作空间初始化
- `todo` 模式怎么用
- `openspec` 模式怎么用
- 每一步执行什么命令
- 每一步如何让 AI 帮你操作

## 1. 前置条件

需要满足：

- 本地已经安装好 skill
- 目标代码仓库已经在本地
- 本地可用 `python3`
- 存在 `~/.super-engineer/skill-config.yml`

如果 `~/.super-engineer/skill-config.yml` 不存在，第一次执行 `init` 时会自动生成模板，并暂停当前流程。

## 2. 示例目录

`todo` 模式下，推荐目录结构：

```text
your-workspace/
├── workspace.yml
├── todo.md
└── output/

your-project/
├── docs/
├── item-user-service/
└── ...
```

`openspec` 模式下，推荐目录结构：

```text
your-spec-repo/
└── openspec/
    ├── specs/
    └── changes/
        └── add-user-phone-filter/
            ├── proposal.md
            ├── design.md
            ├── tasks.md
            └── specs/
```

## 3. 什么时候用哪种模式

适合 `todo` 模式的场景：

- 需求比较局部，主要是工程交付问题
- 目标是尽快推进实现
- 本次需求不要求长期规格治理

适合 `openspec` 模式的场景：

- 需求已经在 OpenSpec change 里定义
- 需求跨多个服务或业务域
- 希望把执行结果回写给 OpenSpec，后续做 archive

## 4. 工作空间初始化

### 4.1 `todo` 模式 `workspace.yml`

```yaml
version: 1
mode: manual
workflow_source: todo
todo_file: /absolute/path/to/your-workspace/todo.md
reference_files:
  - /absolute/path/to/your-project/docs/project-intro.md
  - /absolute/path/to/your-project/docs/dev-rules.md
code_path: /absolute/path/to/your-project
output_dir: /absolute/path/to/your-workspace/output
```

### 4.2 `todo.md` 示例

```md
# 限制条件
- 修改的服务是 item-user-service
- 需要兼容旧的查询参数行为

# 待办事项

## 用户列表
- [ ] 用户列表接口增加手机号精确筛选
1. 仅支持管理员角色使用
2. 前端为空时不传该参数
3. 后端需要兼容旧参数

## 测试
- [ ] 补齐 controller 和 service 层测试
```

### 4.3 `openspec` 模式 `workspace.yml`

```yaml
version: 1
mode: manual
workflow_source: openspec
todo_file: /absolute/path/to/your-workspace/todo.generated.md
reference_files: []
code_path: /absolute/path/to/your-project
output_dir: /absolute/path/to/your-workspace/output
openspec:
  change_dir: /absolute/path/to/your-spec-repo/openspec/changes/add-user-phone-filter
```

### 4.4 OpenSpec change 示例

`proposal.md`

```md
# Proposal

## Background
客服需要通过手机号精确定位经销商用户。

## Scope
- 经销商用户列表接口
- controller / service / query 链路
- 对应测试
```

`design.md`

```md
# Design

## Compatibility
- 当 `phone` 为空时，保持旧查询行为不变
- 不涉及数据库 schema 变更
```

`tasks.md`

```md
# Tasks

## API
- [ ] 为经销商用户列表接口增加手机号精确筛选
- [ ] 当 phone 为空时保持旧行为

## Testing
- [ ] 补充 controller 测试
- [ ] 补充 service 测试
```

## 5. 分阶段操作说明

### 步骤 1：初始化

执行命令：

```bash
python3 super-engineer-workflow/scripts/run-workflow.py init --workspace /absolute/path/to/your-workspace
```

预期结果：

- 校验 `workspace.yml`
- 创建 `.super-engineer/`
- `todo` 模式下：如果 `todo.md` 不存在则自动生成
- `openspec` 模式下：自动生成 `todo.generated.md` 和 `openspec-bridge-context.json`

建议给 AI 的提示词：

```text
使用当前工作空间里的 super-engineer-workflow。
先执行 init，检查 workspace 是否可用。
如果 workflow_source=openspec，请额外确认是否已经从 tasks.md 生成了桥接 todo。
如果有配置问题，直接指出具体字段和修复建议。
```

### 步骤 2：生成计划

执行命令：

```bash
python3 super-engineer-workflow/scripts/run-workflow.py plan --workspace /absolute/path/to/your-workspace
```

预期结果：

- 创建新的 session
- 自动执行 `discover`
- 生成 `plan.json` 和 `plan.md`
- `openspec` 模式下会把 `bridge_context` 带入计划

建议给 AI 的提示词：

```text
执行当前工作空间的 plan 阶段。
然后只总结以下内容：
1. 命中的目标仓库
2. 影响文件或候选文件
3. 验收标准
4. 主要风险
先不要开始改代码。
```

### 步骤 3：开始实现

执行命令：

```bash
python3 super-engineer-workflow/scripts/run-workflow.py start-implement --workspace /absolute/path/to/your-workspace
```

预期结果：

- 当前 session 状态进入 `implement`
- AI 可以开始按 `plan.json` 实施修改

建议给 AI 的提示词：

```text
以当前 session 的 plan.json 作为唯一实现基线。
只在计划范围内改代码。
如果代码现实和计划不一致，先说明差异，再继续实现。
```

### 步骤 4：结束实现并执行自查

执行命令：

```bash
python3 super-engineer-workflow/scripts/run-workflow.py finish-implement --workspace /absolute/path/to/your-workspace
```

预期结果：

- 自动执行 `self-check`
- 生成 `self-check.json` 和 `self-check.md`
- 如果没有代码改动或存在阻塞项，会直接阻塞

建议给 AI 的提示词：

```text
结束当前 session 的实现阶段，并执行 self-check。
告诉我：
1. 有没有 blocking finding
2. 有没有测试改动
3. 有没有计划外文件
```

### 步骤 5：执行 review

执行命令：

```bash
python3 super-engineer-workflow/scripts/run-workflow.py review --workspace /absolute/path/to/your-workspace
```

预期结果：

- 生成 `review.json` 和 `review.md`
- `openspec` 模式下自动生成或更新 `execution-summary.json` / `execution-summary.md`

建议给 AI 的提示词：

```text
执行当前 session 的 review。
只输出：
1. review gate 结果
2. blocking findings
3. warning findings
4. 测试覆盖风险
如果 workflow_source=openspec，请确认 execution-summary 已回写。
```

### 步骤 6：执行 verify

执行命令：

```bash
python3 super-engineer-workflow/scripts/run-workflow.py verify --workspace /absolute/path/to/your-workspace
```

预期结果：

- 执行仓库 verify 命令
- 生成 `verify.json` 和 `verify.md`
- `openspec` 模式下自动更新 `execution-summary.json`

建议给 AI 的提示词：

```text
执行当前 session 的 verify。
总结以下内容：
1. verify 总体结果
2. 每个仓库的执行结果
3. 当前 workflow 是 done 还是 blocked
4. 还剩哪些 residual risks
```

## 6. OpenSpec 模式下的额外步骤

### 步骤 7：准备归档

执行命令：

```bash
python3 super-engineer-workflow/scripts/run-workflow.py prepare-archive-openspec --workspace /absolute/path/to/your-workspace
```

预期结果：

- 读取 `execution-summary.json`
- 生成 `archive-input.json`
- 生成 `merge-preview.md`
- 检测 spec baseline 是否变化
- 给出 `merge_mode`

建议给 AI 的提示词：

```text
为当前 OpenSpec change 执行 prepare-archive-openspec。
告诉我：
1. archive_ready 是 true 还是 false
2. merge_mode 是什么
3. blockers 是什么
4. 有没有 spec_conflicts
只有 merge_mode=safe_merge 时才建议继续归档。
```

### 步骤 8：执行归档

执行命令：

```bash
python3 super-engineer-workflow/scripts/run-workflow.py archive-openspec --workspace /absolute/path/to/your-workspace
```

预期结果：

- 将 `change/specs/` 合并到主 `openspec/specs/`
- 将当前 change 移动到 `openspec/changes/archive/YYYY-MM-DD-<change>/`
- 生成 `archive-result.json` 和 `archive-result.md`

建议给 AI 的提示词：

```text
仅在满足以下条件时执行 archive-openspec：
- archive_ready=true
- merge_mode=safe_merge
- spec_conflicts 为空
归档后告诉我：
1. 哪些 spec 文件被同步
2. change 被归档到了哪里
```

## 7. 常看文件

执行过程中建议重点看这些文件。

当前 session：

- `<workspace>/.super-engineer/current-session.json`
- `<workspace>/.super-engineer/sessions/<session_id>/plan.json`
- `<workspace>/.super-engineer/sessions/<session_id>/review.json`
- `<workspace>/.super-engineer/sessions/<session_id>/verify.json`

OpenSpec 模式下：

- `<workspace>/.super-engineer/openspec-bridge-context.json`
- `<change_dir>/super-engineer/execution-summary.json`
- `<change_dir>/super-engineer/archive-input.json`
- `<change_dir>/super-engineer/archive-result.json`

## 8. 推荐操作方式

比较稳的方式是：

1. 人先准备 `workspace.yml`
2. 人或 AI 执行 `init`
3. AI 执行 `plan`
4. 人看 `plan.md`
5. AI 实现并执行 `finish-implement`
6. 人看 `review.md`
7. AI 执行 `verify`
8. `openspec` 模式下，AI 执行 `prepare-archive-openspec`
9. 人确认 `merge_mode=safe_merge`
10. AI 执行 `archive-openspec`

## 9. 出错时怎么处理

如果 `init` 失败：

- 检查 `workspace.yml`
- 检查路径是否都是绝对路径
- 检查 `~/.super-engineer/skill-config.yml` 是否已经补齐

如果 `plan` 失败：

- 检查 `todo.md` 或 `tasks.md` 是否有实际内容
- 检查目标服务名是否明确

如果 `review` 被阻塞：

- 先修复 blocking finding
- 再重新执行 `review`

如果 `verify` 被阻塞：

- 修复失败命令
- 或补齐缺失的 verify 命令
- 再重新执行 `verify`

如果 `prepare-archive-openspec` 返回 `manual_merge_required`：

- 对比当前主 `openspec/specs/` 和本次 change 的 delta specs
- 先人工处理冲突
- 再重新执行 `prepare-archive-openspec`

## 10. 最小提示词集合

如果你不想每一步都写很多提示词，可以直接用下面这组最小提示词。

`init`

```text
使用当前工作空间的 super-engineer-workflow，先执行 init，并告诉我 workspace 是否已就绪。
```

`plan`

```text
执行当前 workspace 的 plan，并总结实现范围、验收标准和主要风险。
```

`implement`

```text
以当前 session 的 plan 作为基线，在范围内完成实现。
```

`review`

```text
执行 review，只告诉我 gate 结果、blocking findings 和 warning findings。
```

`verify`

```text
执行 verify，告诉我 workflow 是 done 还是 blocked，并总结每个仓库的结果。
```

`archive`

```text
为当前 OpenSpec change 执行 prepare-archive-openspec，只有在 safe_merge 时才继续 archive-openspec。
```

## 11. `auto` 模式操作说明

`auto` 模式和 `manual` 模式最大的区别是：

- `manual` 模式下，plan / implement / review 之间会停下来等待确认
- `auto` 模式下，只要没有硬阻塞，就会持续往后推进

### 11.1 配置怎么改

只需要把 `workspace.yml` 里的：

```yaml
mode: manual
```

改成：

```yaml
mode: auto
```

`todo` 模式示例：

```yaml
version: 1
mode: auto
workflow_source: todo
todo_file: /absolute/path/to/your-workspace/todo.md
reference_files:
  - /absolute/path/to/your-project/docs/project-intro.md
code_path: /absolute/path/to/your-project
output_dir: /absolute/path/to/your-workspace/output
```

`openspec` 模式示例：

```yaml
version: 1
mode: auto
workflow_source: openspec
todo_file: /absolute/path/to/your-workspace/todo.generated.md
reference_files: []
code_path: /absolute/path/to/your-project
output_dir: /absolute/path/to/your-workspace/output
openspec:
  change_dir: /absolute/path/to/your-spec-repo/openspec/changes/add-user-phone-filter
```

### 11.2 推荐命令顺序

`todo` 模式：

```bash
python3 super-engineer-workflow/scripts/run-workflow.py init --workspace /absolute/path/to/your-workspace
python3 super-engineer-workflow/scripts/run-workflow.py plan --workspace /absolute/path/to/your-workspace
python3 super-engineer-workflow/scripts/run-workflow.py start-implement --workspace /absolute/path/to/your-workspace
python3 super-engineer-workflow/scripts/run-workflow.py finish-implement --workspace /absolute/path/to/your-workspace
```

`openspec` 模式：

```bash
python3 super-engineer-workflow/scripts/run-workflow.py init --workspace /absolute/path/to/your-workspace
python3 super-engineer-workflow/scripts/run-workflow.py plan --workspace /absolute/path/to/your-workspace
python3 super-engineer-workflow/scripts/run-workflow.py start-implement --workspace /absolute/path/to/your-workspace
python3 super-engineer-workflow/scripts/run-workflow.py finish-implement --workspace /absolute/path/to/your-workspace
python3 super-engineer-workflow/scripts/run-workflow.py prepare-archive-openspec --workspace /absolute/path/to/your-workspace
```

说明：

- `finish-implement` 在 `auto` 模式下会自动继续执行 `self-check -> review -> verify`
- 一般不需要再单独手工执行 `review` 和 `verify`
- `archive-openspec` 仍建议显式执行，不建议无条件自动归档

### 11.3 AI 提示词怎么写

计划阶段：

```text
执行当前工作空间的 plan。
总结目标仓库、影响范围、验收标准和主要风险。
如果没有硬阻塞，不要停在 plan 阶段等待确认。
```

实现阶段：

```text
以当前 session 的 plan.json 作为唯一实现基线。
完成代码修改后，继续执行 self-check、review、verify。
除非出现 blocking finding 或 verify 失败，否则不要中途停下等待确认。
```

OpenSpec 归档准备：

```text
如果当前 workflow_source=openspec，并且 verify 已通过，执行 prepare-archive-openspec。
告诉我 archive_ready、merge_mode 和 spec_conflicts。
只有 merge_mode=safe_merge 时才建议继续 archive-openspec。
```

### 11.4 `auto` 模式什么时候会停

即使是 `auto` 模式，遇到以下情况也应该停：

- `workspace.yml` 不合法
- `todo.md` 或 `tasks.md` 缺失
- 无法定位目标仓库
- self-check 出现阻塞项
- review 出现阻塞项
- verify 失败
- `prepare-archive-openspec` 返回 `manual_merge_required`

所以 `auto` 模式不是“无脑一直跑”，而是：

**没有阻塞就连续推进，有阻塞就停下来暴露问题。**
